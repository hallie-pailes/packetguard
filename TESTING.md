## Setup for the real experiments
1. Test server: `online-mode=false`, `network-compression-threshold=-1`, one survival player (the bot or you).
2. Fill `baseline/profiles/<version>.json` packet ids and layouts; set `verified` true. **Validate**: run
   `relay --mode monitor` during normal play; `parse_errors` must stay 0 and rejections ~0.
3. Put one `config.json` in the mod's config folder; give the relay the same file via `--config`.

## Configurations
| | Mod | Proxy | Purpose |
|---|---|---|---|
| A | off | passthrough (+inject) | Does the attack work at all (ground truth) |
| B | off | filter (+inject) | Network baseline |
| C | ENFORCE | passthrough (+inject) | Mod alone |
| D | ENFORCE | filter (+inject) | Both |
| C-PACKET / C-CONN | ENFORCE, `visibilityCeiling` PACKET / CONNECTION | passthrough | Ablation: mod limited to proxy-level information. Should match B; if not, explain. |
| M | MONITOR + shadowEvaluation | passthrough | One run: `minVisibility` per event |
| E (optional) | SS Anti-Cheat Stack etc. | passthrough | Community tool comparison |

Run: `python -m baseline.relay --mode filter --config config.json --upstream-port 25565 --listen-port 25566 --inject baseline/attacks.example.json --out out/B`
Then: `python tools/analyze.py attacks --attack-log out/B/attack_log.jsonl --proxy-events out/B/events.jsonl --mod-events <server>/packetguard/events.jsonl`

## Metrics to report
1. **Detection**: per attack class, flagged and blocked, mod vs proxy (attacks 1-11; expect proxy to catch only PACKET/CONNECTION classes: A3, A4, A8, A9, A11).
2. **Confirm the attack is real**: in A, check server-side effect (item moved, block broken, log line). Without this, "blocked" proves nothing.
3. **False positives**: 30+ min of ordinary play (inventory shuffles, chests, shift-click spam, creative building, mod GUIs) in MONITOR; `analyze.py benign`. Also a deliberate stress: fast legitimate clicking.
4. **Overhead**: `analyze.py latency` (p50/p99 ns per packet, mod) and server MSPT with/without mod under an N-bot load; proxy added latency measured by ping through it.
5. **Hot reload / robustness**: edit config during a run; bad JSON keeps old config.
